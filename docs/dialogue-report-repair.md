# 情境对话小结兼容修复（2026-11-04）

## 原因与范围

长对话复测中，AI 完整返回了 JSON，finish_reason 为 stop，没有触发输出截断；但 grammarWeaknesses 返回对象列表，后端 ReportSchema 只接受字符串列表，整份小结因此失败。这个字段随后本来就会由服务器从真实纠错重新汇总，不应先让服务商的可选统计格式阻止其他合格内容保存。

这说明本次故障的直接原因是格式兼容，并非轮数达到上限。不据此承诺所有长对话都不会遇到网络超时或模型输出限制。

## 修复

- validateReport 在结构校验前移除服务商提供的 grammarWeaknesses 内容，保持从真实用户纠错计算类别。模型返回字符串、对象、null 或缺少该字段时，均不会产生未经验证的语法证据。
- 小结提示词明确要求此字段为空数组，由后端统计。
- 其他字段继续严格校验：摘要必填、纠错必须引用用户原文、薄弱词必须有实际尝试或求助证据、强化练习必须使用对应词。没有放宽 SRS 证据要求。
- 不改变对话轮数、AI 调用额度和三次小结重试上限。

## 已失败小结的补回

restoreFailedDialogueReport 仅供服务器维护，不开放 HTTP 接口。用户明确允许再次发送原有对话到原服务商后，可复用已取得并校验通过的响应补回原会话。恢复时检查账号归属、失败状态、对话轮次和操作租约；小结、词汇证据、复习进度和后续任务在同一事务提交。重复恢复不重复计入学习记录，也不额外调用 AI。

诊断的调用用量先记入 dialogue_daily_usage，恢复时只把同一笔用量关联回会话，不重复消耗模型或追加每日调用。完整诊断响应仅保存在原服务器私有目录，不进入 Git、聊天或本机报告。

## 验证

回归覆盖服务商返回语法对象、无证据语法统计、真实引文与薄弱词校验，以及 17 轮对话结束生成小结。另验证历史失败达到重试上限后的维护恢复、错误账号、轮次不符、无效内容、重复提交和 SRS 只计一次。

本次为后端修复，不需要重新打包安卓 App。部署后保留原对话，并补回用户已授权修复的小结。
