# 情境对话使用体验整改

本轮依据实际购物对话中“停留第一阶段、缺少中文、词汇少、不会开始、语音只能回放最后一段”等反馈整改。

## 用户可见变化

- 默认进入经典场景，明确“选场景 → 调整词汇与长度 → 开始交流”。主要按钮直接开聊，认识词汇是独立的可选入口。
- 九个经典场景各提供 12 个情境词，支持 4/8/12 档和 4—12 个微调。选择数量只确定本轮目标，不把没用出的词当成已掌握。
- `bank` 不再出现在新场景库，替换为机场出行；历史 bank 对话、收藏与词义记录继续兼容，不删除旧数据。
- 酒店、购物、餐厅、面试、校园、机场按实际职责安排多角色；图书馆和咖啡店桌边服务等合理单人路线保留单人。按当前对象回复，保留身份与共同任务进度，不生成多人剧本。
- 练习长度可选 16/32/64/96/160/240 轮。新界面默认 64 轮，可在同一对话增加 32 轮，单会话最多 240 轮；仍受用户和供应商的调用额度约束。达到所选长度保留进度，不强制证明场景已掌握。
- 认识词汇展示例句，选项使用同一个词的其他真实义项，点击即保存。经典词有人工编写的义项对照；自定义词缺乏可靠多义资料时不借用其他单词的释义编造干扰项。
- 开场和阶段开场有中文译文，用户可切换显示；英文直接可见。可选听力理解收进展开区，显示过文字的表现不会标为盲听成功。
- 当前阶段卡紧贴对话，去掉重复目标，允许结合本阶段多次表达核对。AI 提供原文证据后，服务端只推进一个阶段并开启下一话题；用户可关闭自动推进，或手动跳过，未核实目标仍保留。
- 模型提示明确要求继续追问未确认的信息，避免只说“谢谢，有问题再找我”而让练习中断；纠错与目标完成分别处理，小语法错误不一律阻断交流进度。
- 可切换完整时间线与当前对象记录，查看转场提示。任务、词汇、完整路线和录音设备排查收进展开区，手机端优先显示对话。

## 录音与速度

原录音与发送后的回答配对，按 API 地址、账号、会话和轮次在本机 IndexedDB 保存，可翻回重听和单条删除；不另上传一份录音供云端长期保存。此设备存储不足或不支持时降级为当前页面回放并提示。换设备不会自动获得本机录音。

录音使用单声道与 16kHz 的浏览器偏好参数、32kbps 编码请求，实际格式仍由浏览器决定。新版识别接口直接上传音频，省去 Base64 扩容，保留原 JSON 接口兼容旧客户端；在登录后校验时长、大小与容器签名。识别服务商自身的耗时不能由减少传输量保证。

朗读速度可选 0.85/1/1.15/1.3 倍；有本地英语声音时优先使用本地声音。其他设备继续使用 Kokoro，短句音频按登录身份缓存，调整句子播放速度复用原音频，减少重复合成。

## 验证及边界

完整回归 733 项：732 通过、0 失败、1 项原有可选集成测试跳过。包含阶段原文累计、自动转场、角色范围、轮次延长与冲突、历史场景、同词义项、录音隔离、二进制上传和原有学习功能；生产构建通过。

浏览器已用独立本机账号实际打开新入口，看到九个经典场景、机场替换、购物多角色、词数选择、64 轮可选和两个清晰入口。进一步操作时检测到用户输入，因此停止自动操作，没有把入口检查称为完整浏览器验收。文字模型的自动化测试使用模拟响应；真实对话连贯性、识别耗时、不同手机录音及 IndexedDB 行为仍需专项实测。

本轮无需新增数据库迁移，不重建账号、词库、报告或学习记录。发布时沿用既有备份及保留配置、数据库卷与语音服务的流程。
