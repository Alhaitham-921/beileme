# 邮箱验证与密码找回（已实现，2026-11-02）

## 使用

1. 管理员在server/.env配置SMTP_HOST、SMTP_PORT、SMTP_SECURE、SMTP_USER、SMTP_PASS（QQ授权码而非登录密码）和SMTP_FROM_NAME。授权码不进入前端/APK，不提交Git。
2. 用户登录后进入偏好设置，点击“账号安全 · 邮箱验证”，输入当前密码发送验证邮件，将邮件中32位码复制回App完成验证。
3. 忘记密码时在登录页点“忘记密码？”，输入已验证邮箱获取重置码，粘贴32位码并输入两次新密码。成功后重新登录，原来的所有设备令牌失效。
4. 代码使用QQ SMTP发送；实际邮件可能延迟或进入垃圾箱，服务器接受发送不代表已进入收件箱。新用户注册后也需先做邮箱验证。仅手机号账号或未验证邮箱的历史账号忘记密码后，需要可信管理员人工核验，不能仅凭邮箱直接重置。

## 安全和运行

迁移019只新增验证时间字段、一次性挑战表和限流表，不重置账号数据。随机码128bit，数据库只存SHA256哈希；15分钟有效，重发旧码失效，验证/找回用途隔离，并绑定用户当前token_version。重置事务锁定用户与挑战，一次性消耗并撤销刷新令牌。不会删除学习记录、收藏、场景和API配置。

每邮箱重置请求60秒间隔、每小时5次，每来源IP每小时20次；确认每IP每15分钟30次；所有邮件申请总计每日100次。限流持久存储，单进程邮件队列最多10个待办。当前为单机演示实现，公网多实例应改成持久邮件任务队列；发送前进程退出可能导致待办丢失，用户可间隔60秒重试。限流使用socket来源地址，未来反向代理需明确可信代理配置，否则多个用户可能共享同一限额。

对不存在、未验证和可恢复邮箱返回同样的202提示，邮件后台发送避免用SMTP耗时枚举账号。发送失败时码会失效，日志仅含通用提示；不会向客户端返回重置码或授权码。密码变更后发送通知，通知发送失败不回滚密码。

QQ环境使用系统IPv4 DNS解析，并用原域名执行TLS SNI和证书校验，不关闭TLS验证。邮件授权码仅保存在本地配置，数据库不存该授权码。

## 迁移和测试

npm ci && npm run db:migrate，重启后端。测试见server/tests/integration.passwordRecovery.test.js，仅用独立测试库和模拟邮件，不触发真实发送。首次真实测试向配置发信邮箱自身发送“背了么 · 邮件服务配置测试”；收件需用户确认。
