# 情境自动配图与分镜

生成自定义情境后，系统按地点、双方角色、任务和开场在后台生成一张图片，用户可以直接开始聊天。对话模型会在正常回复中附带可选的场景变化说明；只有地点、可见行动或内容明显推进时才追加一幕，不为普通追问和纠错逐句生图。每轮只生成一个画面，已有分镜按对话顺序保留，可横向浏览。

「偏好设置 → 学习环境 → 情境自动生图」默认开启，按账号保存。关闭后不再自动发起图片请求，已有图片仍可查看；已经提交的生图请求仍可能完成。服务器未配置生图服务时仅保留设置，不发起请求。

角色描述在同一个故事中保持一致，以降低换幕时外貌、服装变化，但文字生图不能保证人物完全一致。画面采用自然、低至中等饱和度配色和干净细腻的线条，不固定色板，不生成文字或对白框。原单词记忆图也去除了固定色系和背景色限制。

## 次数、等待与恢复

- 复用服务器的 `WORD_IMAGE_*` 服务配置，与记忆图、换图共用 `WORD_IMAGE_DAILY_QUOTA`（默认每日 5 次尝试，包括失败请求）。
- 同一场景开场图、同一轮分镜按账号去重。后续分镜至少间隔两轮，每个会话最多六幕，尚未完成的同会话图片不重复并发生成。
- 图片生成不占用对话事务或长时间持有数据库连接，失败不丢失文字对话和已有图片。
- 后台任务用数据库租约和令牌去重。进程中断后，过期任务显示失败，由用户主动重试，不通过刷新页面偷偷重复付费调用。
- 生图使用文字描述来保持情节连贯，不将生成图中可能不准确的细节作为词汇掌握的评分依据。
- 图片通过带登录校验的私有接口读取，不能跨账号获取。

## 更新与检查

运行 `npm run db:migrate` 应用只新增表的 `033_dialogue_illustrations.sql`，重启后端并重新构建页面。安卓需要重新打包才能显示新入口与设置。

相关检查：

```text
node --test --test-isolation=none --test-force-exit server/tests/api.dialogueIllustrations.test.js server/tests/unit.dialogueIllustrations.test.js
npm run build
```

自动化使用独立测试库和模拟图片供应商，不调用收费生图服务。测试脚手架会核对连接池实际数据库名，禁止因模块导入顺序误用开发库。
