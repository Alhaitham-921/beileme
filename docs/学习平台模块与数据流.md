# 学习平台模块与数据流

自测、错词本和看图回忆是产品功能。网页通过同一个 Node API 读写账号数据。本地开发可分别启动网页和 API，Docker 部署由网页入口、Node API、MySQL 和 Kokoro 语音组成。部署配置见 [Docker 部署说明](Docker部署.md)。

| 位置 | 负责的内容 |
| --- | --- |
| 网页与浏览器 | 渲染短测和看图练习、随机排列图选项、展示反馈。内置练习图随网页发布，已加载的个人图片可由浏览器缓存。 |
| Node API | 校验账号、出题与计分、查询历史、组织 AI 请求、生成和转换图片。 |
| MySQL | 保存账号、词书、学习和复习记录、短测作答、完成时间、分档成绩、AI 建议及个人记忆图。 |
| 部署环境 | 提供数据库连接、服务端密钥和第三方服务配置。各自部署的 MySQL 数据独立保存。 |
| 外部 AI 服务 | 短测建议接收按档汇总的答题数据。记忆图的文字模型接收词义及场景线索，绘图服务接收生成后的场景描述。 |

## 起点短测与复测

`网页提交作答 → Node 计分 → assessment_sessions → 网页显示本次成绩`

复测页面查询同账号、同词书、测评方法及题库版本可比较的已完成短测。页面直接展示本次和上次各档答对数、题量、不确定数及答对率变化。综合报告最多参考此前二十次可比较自测，跨日趋势使用最近五个测试日，至少有三个测试日才描述持续变化。逐题记录、近期练习和趋势规则见 [自测历史关联与综合解释](assessment-history.md)。

`可比较的自测与近期练习 → 自动分析 → 保存报告 → 网页展示`

用户可以按需点击「生成综合解释」，由 AI 从报告已核对的结论和练习建议中选择重点。解释按账号和本次自测保存，可刷新查看。验证时，同一账号在同一词书连续完成 A/B 两卷，再从历史打开第一卷检查结果。

## 错词记忆图与看图回忆

`错词选择义项 → Node 登记生成任务 → 文字模型构思场景 → 图像模型出图 → MySQL 保存 WebP`

个人图按账号、单词和义项保存在 `word_memory_images`。用户可以继续答题，之后从错题本或看图回忆读取。看图回忆从已有图片组题，方位介词练习使用随网页发布的固定示意图。见 [错词记忆图和看图回忆](word-learning-cards.md)。

## 演示验收

1. 在「今日回顾 → 看图回忆」开始内置题，再点「练习方位介词」。作答前只显示英文词和图片，提交后用图解核对 `in`、`on`、`under`、`between` 的区别。
2. 请没看过答案的同学完成四题，记录每题是否选对和误选的关系。再用同样的方法检查几张待验证的抽象词图片，记下最常被理解成的义项。
3. 从错题本生成新图，在 API 日志找 `Generation completed`，记录场景构思 `sceneMs`、图像服务响应 `providerMs`、下载 `downloadMs`、转换 `normalizeMs` 和含存储在内的 `totalMs`。在浏览器性能面板读取 `image-recall.*.first-ready`，它记录进入一组题到首题所有图片可作答的时间。内置题、介词题和个人图分别测量。

2026 年 11 月 15 日的本地单次测量使用 `carefully` 示例和固定场景文本。硅基流动响应 3.84 秒、下载 0.66 秒、WebP 转换 0.15 秒，后台写入合计 4.66 秒。生成图画出了双手端水，遗漏了跨过地面障碍的动作，随后把提示词示例收敛到保持满碗水平这一项可见线索。浏览器测试数据下，内置题、方位介词题、个人图题分别在 20、9、11 毫秒后可作答。文字模型耗时和实际部署时的首题耗时需要用部署环境的数据再测。
