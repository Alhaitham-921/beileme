# 「背了么」产品需求文档 (PRD)

版本：V0.1（MVP 规划稿）
文档类型：产品需求文档
适用范围：Web 应用（后续可扩展至 App）

---

## 一、产品定位

**一句话定位**：一款用 AI 把"背单词"变成"用单词"的个性化英语学习工具——单词不是孤立记忆，而是被 AI 编织进文章、题目、游戏和错题诊断里，越背越懂你。

**核心差异化**：市面上的背单词软件（如墨墨、扇贝、百词斩）解决的是"重复"，「背了么」要解决的是"为什么记不住"和"记住之后能不能用"。具体体现在三点：

1. **千人千面**：同一个单词表，不同用户看到的例句、文章、题目都不同，因为 AI 会结合该用户的错题历史、犹豫时长、易混词记录来动态生成内容。
2. **归因驱动复习**：不只是"错了就多背几次"，而是分析错因（形近词混淆？中文释义记混？反应慢是没记住还是不自信？），针对性生成巩固内容。
3. **背完能用**：单词学完不是终点，AI 会生成含目标词的短文 + 阅读理解题，检验"是否真的认识这个词在句子里的样子"。

## 二、目标用户与使用场景

### 2.1 用户画像

| 用户群体 | 核心诉求 | 备注 |
|---|---|---|
| 中高考考生 | 考纲词汇覆盖、题型适配、每日打卡 | 需贴合中高考阅读理解风格 |
| 四六级考生 | 短期内冲刺、高频词优先、真题风格阅读 | 时间紧，需要计划表 |
| 考研考生 | 词汇量大、长难句阅读能力 | 文章难度需可调 |
| 雅思/托福考生 | 学术词汇、写作词汇迁移、AI 作文批改（后续功能） | 对"用词造句"需求最强 |
| 泛兴趣学习者 | 无考试压力，兴趣驱动、游戏化体验 | 更看重趣味性和低门槛 |

### 2.2 典型使用场景

- 场景一：用户早起通勤路上，打开 App 完成当日 15 个新词 + 复习 30 个旧词的 to-do。
- 场景二：用户发现某个词反复记错，系统识别出是和形近词混淆，生成对比记忆卡片。
- 场景三：用户背完一组词后，AI 生成一篇 150 词的小短文，里面自然嵌入本组的 8 个新词，阅读后回答 3 道理解题。
- 场景四：用户情绪疲惫，不想学新词，选择玩"中英消消乐"或"拼词游戏"放松式复习。

## 四、详细功能需求

### 4.1 Onboarding：新用户需求分析问卷

**目的**：首次登录时，通过问答生成用户学习画像，作为后续 AI 生成内容和计划的输入变量之一（也是保证"千人千面"的关键输入源之一）。

**问卷内容（示例，均为可跳过/可后续修改）**：

1. 你目前的学习目标是？（单选）
   - 中考 / 高考 / 四级 / 六级 / 考研 / 雅思 / 托福 / 纯兴趣学习 / 自定义词书
2. 距离考试还有多久？（用于计算每日任务量）
3. 你的自我评估词汇量？（不确定 / 1000以下 / 1000-3000 / 3000-6000 / 6000以上，可提供一个 3 分钟摸底测试代替自评）
4. 每天愿意投入的学习时长？（5-10分钟 / 15-20分钟 / 30分钟以上 / 自定义）
5. 你更倾向哪种记忆方式？（多选：例句记忆 / 词根词缀 / 图像联想 / 语境阅读 / 游戏化）
6. 是否需要写作辅助（后续作文批改功能的前置调研，不强制）

**输出**：
- 生成学习目标词书（如四级核心词、雅思核心词等，需内置或可导入词书库）
- 生成每日新词量 + 复习量的初始 Todo 计划
- 生成用户画像 JSON，供后续 AI 生成模块调用（如"该用户偏好语境阅读式记忆"会影响短文生成 prompt 的侧重点）

摸底测试建议：可选功能，给 20-30 个不同难度单词快速测试，用「认识/模糊/不认识」三档反馈，比自评更准确。

### 4.2 背词核心引擎

#### 4.2.1 背词交互流程

单个单词的标准学习卡片包含：单词本身、音标、发音（TTS）、词性、中文释义选项（用于选择题式背词，也可切换为拼写模式）。

流程：
1. 展示单词 → 用户选择/拼写释义
2. 系统记录：**作答结果（对/错）**、**犹豫时长**（从展示到第一次交互的时间）、**具体选错的干扰项**
3. 根据结果进入不同分支：
   - 答对且反应快 → 判定"熟练"，按 SRS 算法拉长下次复习间隔
   - 答对但犹豫久 → 判定"半熟"，标记为"低置信度正确"，复习间隔适度缩短
   - 答错 → 触发**错因分析引擎**

#### 4.2.2 记忆算法（间隔重复 SRS）

- 基于 SM-2 / FSRS 思路的间隔重复算法，输入变量除常规的"是否记住"外，额外纳入：
  - 犹豫时长（归一化为置信度分数）
  - 历史错误次数
  - 是否属于易混词组（易混词组的复习间隔要更短，因为遗忘/混淆概率更高）
- 每个单词维护一个"记忆强度"分值，用于生成复习优先级队列。

#### 4.2.3 错因分析引擎（核心亮点功能）

当用户背单词答错时，系统按以下维度综合判断错因类型：

| 判断依据 | 可能错因 | 系统响应 |
|---|---|---|
| 犹豫时长很短就选错 | 盲猜/完全不认识 | 归为"全新学习"，缩短复习间隔，增加重复次数 |
| 犹豫时长很长最终选错 | 记忆模糊/半知半解 | 标记"低置信度"，优先安排语境化复习（例句/短文） |
| 选择的错误释义属于形近词/近义词的释义 | 词形混淆或语义混淆 | 触发"易混词卡片"，展示对比 |
| 反复在同一组词间答错 | 系统性混淆 | 生成专项巩固练习，集中辨析 |
| 拼写模式下字母顺序错误 | 拼写记忆薄弱 | 推送拼词类小游戏加强 |

**易混词/近义词推荐**：
- 形近词判断：编辑距离（Levenshtein）+ 词根词缀库匹配
- 近义词判断：预置同义词库 或 调用 AI 语义相似度
- 生成"对比记忆卡片"：展示两个词的词形差异高亮、核心语义区别、各自的例句对比，AI 生成一句"如何区分"的记忆口诀或联想小故事

### 4.3 AI 内容生成模块

#### 4.3.1 个性化短文生成

- 触发时机：完成一轮背词（如 10-15 个新词）后，用户可选择"生成巩固短文"
- 输入 Prompt 变量：
  - 本轮目标词列表（必须尽量自然出现在文章中）
  - 用户学习目标（决定文章风格：四六级偏说明文/议论文，雅思托福偏学术文章，中高考偏叙事/应用文）
  - 用户历史易混词（可以在文章中制造对比语境，帮助区分）
  - 难度分级（依据用户词汇量评估结果调整句长、从句复杂度）
  - **随机化因子**：话题池随机抽取（科技/环保/校园/旅行/职场等）+ 生成温度参数，确保相同词表不同用户/不同时间生成的文章不同
- 输出：150-300 词短文，目标词加粗/加下划线标注，文末附生词表对照

#### 4.3.2 阅读理解练习题生成

- 基于上一步生成的短文，AI 自动生成 3-5 道理解题：
  - 词汇题（考查目标词在文中的含义）
  - 细节理解题
  - 推理判断题
  - （四六级/雅思场景）可加长难句翻译题
- 每道题 AI 同步生成解析，答错时展示解析并回链到对应错因

#### 4.3.3 错题巩固内容生成

- 汇总用户本周期内的错词/错题，AI 生成"专项巩固包"：
  - 针对易混词，生成对比记忆卡片（见 4.2.3）
  - 针对反复错的词，生成新一批含该词的例句/短文，用不同语境重复曝光（间隔曝光效应）
  - 生成一份"本周薄弱点小结"，用自然语言告诉用户：你在哪类词上容易出错，哪类题型容易失分

#### 4.3.4（后续迭代功能）配图记忆生成

- 为抽象/难记单词生成联想配图（接入文生图 API），辅助图像记忆法
- 优先级：P2，MVP 阶段先预留接口设计

#### 4.3.5（后续迭代功能）AI 作文批改

- 用户提交作文，AI 按考试标准（四六级/雅思/托福评分标准）批改，给出分项得分、语法错误、用词升级建议
- 可与背词模块联动：识别用户作文中"低级重复用词"，推荐可替换的同义词/更高阶词汇，反哺背词计划
- 优先级：P2

### 4.3.6 AI 模型选型与成本控制

- **默认模型：DeepSeek V4**（性价比优先，作为系统默认的官方额度调用模型；后续若用户自行接入 API，也可切换为其他模型，见 4.8）
- 明确产品优先级：**背单词核心引擎 + AI 内容生成（短文/阅读题/错因巩固）是全产品最核心、最值得投入 AI 算力的部分**；小游戏模块不消耗 AI 调用（见 4.5），从架构上把成本预算集中在刀刃上。
- 成本控制具体措施：
  1. **生成内容复用/缓存**：同一目标词组合（或高度相似的词组合）在短期内被多个用户或同一用户多次触发生成时，优先从缓存池中检索并做轻量个性化改写（如替换少量话题细节），而非每次都全量重新生成，降低 token 消耗。
  2. **分层生成策略**：新词学习环节的例句可优先使用词库自带的预置例句（成本为零），只有"巩固短文""阅读理解题""错因分析建议"这类需要强个性化的场景才实时调用 AI。
  3. **限额与降级机制**：为每个用户设置合理的每日/每月 AI 生成额度（如短文生成次数），超出后可提示"今日 AI 生成次数已用完，可使用预置例句/历史生成内容复习"，避免成本失控，同时不影响背词主链路可用性。
  4. **Prompt 精简**：生成短文/题目的 Prompt 尽量精简、结构化（如仅传必要的用户画像字段摘要而非全量历史数据），控制输入 token 数。
  5. 后续可根据实际调用量评估是否引入更细粒度的用量监控与用户可见的"AI 用量"提示（不强制在 MVP 阶段实现）。

### 4.4 个性化保证机制（重点说明"相同输入不同输出"）

这是用户特别强调的需求，需要在架构层面明确保证。设计如下：

1. **用户画像作为强 Prompt 变量**：即使两个用户背的是同一批词，AI 生成时会注入该用户的画像（学习目标、历史错词、兴趣话题偏好、当前学习阶段），Prompt 本身就不同。
2. **话题/场景随机池**：文章生成前先从话题池按权重随机抽取场景（权重可受用户历史偏好影响，实现"越用越懂你"），保证不同批次生成结果有差异。
3. **生成参数随机化**：调用 AI 时使用非零 temperature，同时在 Prompt 中加入"请勿与常见范文雷同，尽量原创"的约束，避免退化成模板化输出。
4. **历史生成记录去重校验**：系统保存该用户近期生成过的文章摘要向量，新生成内容与历史做相似度校验，过高则重新生成，避免重复。
5. 以上机制不代表"AI 天马行空"，所有生成仍需**严格遵循软件预设的 Prompt 模板与内容规范**（见下方"预设约束"），保证教育属性和内容可控性，不会出现跑题、超纲词汇滥用等问题。

**预设约束（System Prompt 层面规定，无论用户是否接入自定义 API 都强制生效）**：
- 文章/题目必须服务于当前学习目标和词表，不可无关发散
- 用词难度需与用户当前水平匹配（可略高于当前水平，但不可断层）
- 内容需健康、积极、适合学习场景
- 生成结构（短文+生词标注+理解题+解析）为固定格式，AI 只负责填充内容，不改变结构

### 4.5 单词小游戏模块

**触发时机**：完成一轮背词任务后，系统询问"要不要玩一局放松一下？"，非强制。

**重要原则：小游戏模块全部使用固定程序逻辑实现，不调用 AI/大模型**。素材（单词、释义、误导字母/选项）均从用户当前词书和错题本中按规则抽取，判定逻辑也是纯前后端代码实现（如字符串匹配、随机打乱算法）。这样做的好处：
- 响应速度快，无需等待模型生成，游戏体验更流畅
- 不产生 AI 调用成本，游戏可以让用户"随便玩、玩多久都行"，无需做用量限制
- AI 的算力预算可以集中投入到背词核心引擎和文章/题目生成这两个最核心的部分

| 游戏 | 玩法 | 素材来源（纯规则，无 AI） | 训练目标 |
|---|---|---|---|
| 中英消消乐 | 屏幕随机排布英文单词与中文释义方块，点击匹配的英中配对进行消除，限时/限次 | 从当日学习/复习词表中随机抽取，中文释义直接取词库字段 | 巩固词义匹配，趣味重复曝光 |
| 拼词大挑战 | 给出单词的所有正确字母（打乱顺序）+ 若干误导字母，展示中文释义，用户拖拽/点击拼出正确单词 | 正确字母=目标词字母打乱；误导字母按规则生成（如目标词高频形近词的差异字母，或随机高频字母），均为本地算法 | 强化拼写记忆，训练字母顺序敏感度 |
| （可扩展）限时听音辨词 | 播放系统 TTS 发音，多选正确单词/释义 | 混淆项从同词性/同长度词库中规则抽取 | 训练听力反应 |
| （可扩展）单词接龙 | 上一词尾字母作为下一词首字母 | 从词库按首字母索引匹配候选词 | 拓展关联词汇、趣味互动 |

游戏结果同样回写至错因分析引擎（如拼词游戏中反复拼错同一位置字母，可作为"拼写薄弱"的补充证据），这一步只是记录数据供 AI 侧分析使用，游戏本身运行不依赖 AI。

### 4.6 学习计划与 Todo 系统

- Onboarding 后自动生成学习计划：目标词书 ÷ 剩余天数 = 每日新词量，叠加 SRS 算法计算出的当日复习量
- 每日 Todo 卡片：新词 X 个 / 复习 Y 个 / （可选）巩固短文 1 篇 / （可选）游戏 1 局

#### 4.6.1 自适应难度调节（未完成计划时触发）

**目的**：用户没背完计划时，与其让 TA 面对"越欠越多"的压力而放弃，不如主动询问原因并调整，提升长期使用意愿。

**触发逻辑**：次日打开 App 时，若检测到前一日 Todo 未完成（新词/复习未达标），弹出一次轻量提示（非强制打断），例如：

> "昨天的计划没完成，是单词有点难吗？"
> 选项：① 太难了，帮我调整　② 太多了，减点量　③ 就是没顾上，不用调整　④ 跳过，不想选

- 选择"太难了" → 系统降低新词难度分布（如优先从更高频/更基础的词开始），并可适度放慢新词引入速度
- 选择"太多了" → 按比例缩减当日新词量与复习量，剩余未完成的旧任务合并进复习队列，但设置上限（避免无限堆积，例如复习队列超过阈值时优先保证"高遗忘风险词"）
- 选择"没顾上" → 计划量不变，仅记录一次"未完成非难度原因"，用于后续统计但不改变策略
- 选择"跳过" → 不做任何调整，直接进入当日学习，用户可随时在设置里手动调整节奏

调整记录会作为用户画像的一部分，长期反馈进 AI 内容生成的难度控制（如短文/理解题的用词和句式难度）与 SRS 参数。**该询问最多每 2-3 天触发一次**，避免频繁打扰用户体验。

#### 4.6.2 奖励系统（徽章/成就）

- **连续打卡类**：连续学习 3/7/30/100 天解锁对应徽章
- **数量里程碑类**：累计背会 100/500/1000/3000 个单词解锁徽章
- **质量类**：单日正确率 ≥ 95%、单周无"形近词混淆"错误等解锁"精准记忆"类徽章
- **专项挑战类**：完成一次巩固短文阅读全对、连续 5 次拼词游戏一次通关等
- 徽章展示在个人中心，可设置为"学习成就墙"，形成正向反馈，弱化"背单词枯燥"的负面体验
- 优先级：P1（不影响 MVP 主链路，但建议尽早跟进以提升留存）

- 打卡日历，直观展示历史学习记录与连续天数

### 4.9 主界面「背了么」图标与气泡单词彩蛋

**位置**：背单词主界面（学习首页 / 背词页），常驻展示。

**功能概述**：主界面常驻一个「背了么」品牌图标（Q 版吉祥物/Logo，素材见 `背了么图标/1789109106557.png`），带 Q 弹动效；点击后在其周围弹出若干气泡，气泡内先显示用户"最近背过的单词"（英文），约 1 秒后切换为对应的中文释义。作用是为背词主界面增加一个趣味化、有记忆点的轻量彩蛋，弱化背单词的枯燥感，同时顺带做一次"最近所学"的轻量回顾。

**交互细节**：

1. **待机态（Q 弹呼吸）**：图标以较低频率做轻微弹性缩放/呼吸（squash & stretch），营造"软萌"质感；不打断主学习流程。
2. **点击态（压扁回弹）**：点击图标瞬间触发"压扁再回弹"（squash-stretch + 弹簧缓动），随后图标周围呈放射状弹出 5~8 个气泡。
3. **气泡内容与切换**：每个气泡先展示一个最近背过的英文单词，约 1 秒后（带翻转/淡入过渡）切换为对应的中文释义。
4. **气泡行为**：气泡生成后缓慢上浮并逐渐透明、消散，或停留若干秒后自动收起；再次点击可重新生成（单词从"最近所学池"中重新抽取）。
5. **数据来源**：取当前用户 `UserWordProgress` 中学习记录（`history` 时间戳最新）的 N 个单词，中文释义取词库 `Word.definitions` 字段；无学习记录时展示引导文案（如"先去背几个单词吧~"）。

**动效规格（建议）**：
- 待机弹性：scale 1 → 1.05 呼吸，周期约 2s，ease-in-out
- 点击回弹：squash-stretch（scaleX/scaleY 反向形变）+ 弹簧缓动（spring，参考物理弹簧刚度/阻尼）
- 气泡弹出：从中心向外散射，scale 0 → 1 带 overshoot；随后上浮 + 淡出
- 释义切换：英文 → 中文，延迟约 1s，可选 Y 轴翻转或透明度交叉淡入

**技术要点**：
- 前端纯 CSS 动画或 Framer Motion / GSAP 实现，不调用 AI，零成本
- "最近所学词"由后端提供接口（或复用背词流程中前端已有的词缓存），中文释义来自词库字段
- 气泡内单词为"回顾"性质：不计入 SRS 复习队列、不写学习数据（可选：仅记录展示日志用于后续埋点）

**优先级**：P1（不影响 MVP 主学习链路，但实现成本低，建议尽早落地以提升趣味性与品牌记忆点）

## 六、视觉与交互风格建议

用户提到偏好 Claude 的字体与配色，可以此为方向制定设计规范：

- **色彩基调**：暖白/米色背景（而非纯白），主色调用低饱和度的珊瑚橙/陶土色作点缀色，辅以深灰文字，整体温和不刺眼，适合长时间学习使用，避免冷色调科技感带来的紧张感。
- **字体**：正文使用衬线体（如 Source Serif 系列）营造"阅读感"，标题/UI 元素使用简洁无衬线体，中英文混排需保证字重协调。
- **布局**：大量留白，卡片式设计，圆角柔和，减少视觉噪音，突出当前学习内容本身。
- **动效**：轻量、克制的过渡动效（如卡片翻转展示释义），游戏模块可以更活泼但不脱离整体温和基调。主界面「背了么」图标的 Q 弹动效与气泡彩蛋属于趣味化点缀，需控制在局部、不喧宾夺主。
